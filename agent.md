# Developer Guide: Serious Study (Mumbai University Community)

This document provides an exhaustive technical analysis of the Serious Study application from a developer's perspective, focusing on performance, design, security, and architecture.

## 1. Architecture & State Management
- **Framework**: Flutter (SDK ^3.5.4).
- **Pattern**: GetX (MVC-like approach).
    - **Controllers**: Centralized logic in `lib/controller/` (e.g., `AuthController`, `DocumentController`, `HomeController`).
    - **Dependency Injection**: Controllers are initialized in `main.dart` or `layout.dart` using `Get.put()`.
    - **Reactivity**: Uses `Obx`, `GetX`, and `GetBuilder` for granular UI updates without full-screen re-renders.
- **Backend**: Supabase (Serverless).
    - **PostgreSQL**: Relational database with advanced features like Triggers and RPCs.
    - **Real-time**: Leverages Supabase Channels for instant updates on documents and notifications.

## 2. Performance Optimization
- **Reactive State Management**: GetX ensures that only the necessary widgets rebuild when data changes.
- **Local Persistence (Hive)**:
    - High-performance NoSQL storage used for user metadata (`userBox`) and download tracking (`downloadsBox`).
    - Reduces initial load time by caching profile data locally.
- **Media Handling**:
    - **Image Compression**: `ImageHelper` uses `flutter_image_compress` (70% quality, 1024x1024 limit) to reduce bandwidth and storage costs.
    - **Cached Network Images**: `cached_network_image` is used throughout the app to prevent redundant asset downloads.
- **Optimistic UI**:
    - Interactions (likes, dislikes, bookmarks) are updated in the UI immediately before the backend confirmation.
    - `DocumentController` manages state rollbacks if network calls fail.
- **Database Efficiency**:
    - **PostgreSQL RPCs**: Functions like `increment_likes` and `decrement_likes` perform atomic increments on the server, avoiding race conditions and reducing client-side logic.
    - **Batching**: `HomeController` limits initial document fetches to 50 items to optimize initial payload.
    - **Sticky Sort**: Logic in `HomeController` prioritizes "Official" documents at the top of the feed.

## 3. Security Implementation
- **Authentication (JWT)**:
    - Managed by Supabase Auth.
    - Sessions are stored securely and validated via JWT.
- **Row Level Security (RLS)**:
    - Every table in `SUPABASE_SCHEMA.sql` has strict RLS policies.
    - Users can only update their own profiles and delete their own documents.
    - Public read access is granted for community content, while sensitive interactions (notifications, bookmarks) are strictly private.
- **Security Definer RPCs**:
    - Functions like `handle_interaction` use `SECURITY DEFINER` to allow users to update protected counters (e.g., `likes_count`) without having direct write access to those columns.
- **Storage Policies**:
    - Supabase Storage buckets are governed by policies that restrict file uploads/deletions to authenticated owners.
